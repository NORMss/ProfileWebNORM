# Автоперевод сайта на английский

Русская версия сайта живёт на «чистых» адресах (`/`, `/projects`,
`/publications/12`), английская — под префиксом `/en`
(`/en`, `/en/projects`, `/en/publications/12`). Тексты интерфейса переведены
вручную и лежат в коде (`src/lib/i18n/dict.ts`) — они не тратят лимит API.
Через API переводится только контент: посты, описания проектов, README и
блок «обо мне».

Перевод **никогда** не делается локально: на VPS с 2 ГБ ОЗУ модель не поднять.
Ходим в облачный API, результат складываем в SQLite и больше за него не платим.

## Какой сервис выбрать

| Сервис | Бесплатно в месяц | Дальше | Что важно знать |
| --- | --- | --- | --- |
| **Google Cloud Translation** (v2/v3) | 500 000 символов | $20 за 1 млн | Нужен биллинг-аккаунт с картой. Перерасход тарифицируется автоматически, поэтому в приложении есть свой счётчик и стоп-кран. Авторизация обычным API-ключом — SDK и service-account JSON не нужны. |
| **DeepL API Free** | 500 000 символов | нет (жёсткий стоп, HTTP 456) | Лучшее качество для пары ru→en. Есть эндпоинт `/v2/usage` — админка показывает реальный расход, а не только свой счётчик. Free-план новым пользователям может быть недоступен. |
| **Azure AI Translator**, тариф F0 | 2 000 000 символов | нет (HTTP 403, до следующего месяца) | Самый большой бесплатный объём, тариф бессрочный и не переключается на платный сам. Расход виден только в портале Azure. |

Приложение поддерживает все три: `TRANSLATE_PROVIDER=google|deepl|azure`.
Если переменная пуста, берётся первый провайдер, для которого задан ключ.

Оценка расхода: типовой пост в 2 000 символов вместе с заголовком и превью —
около 2 300 символов. Даже на самом скромном лимите в 500 000 это ≈ 200 постов
в месяц, причём каждый пост оплачивается **один раз**: дальше он отдаётся из
таблицы `translations` в SQLite.

## Как подключить Google Cloud Translation

1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект.
2. **APIs & Services → Library** → включить **Cloud Translation API**
   (для проекта должен быть привязан биллинг-аккаунт, иначе API отдаёт 403).
3. **APIs & Services → Credentials → Create credentials → API key**.
4. Ограничить ключ: **Restrict key → Cloud Translation API**, а если сервер
   имеет статический IP — ещё и по IP.
5. В `.env`:

   ```env
   TRANSLATE_PROVIDER=google
   GOOGLE_TRANSLATE_API_KEY=AIza...
   # необязательно: свой потолок, чтобы точно не уйти в платный диапазон
   TRANSLATE_MONTHLY_LIMIT=450000
   ```

6. `docker compose up -d` → админка → вкладка **Переводы** → **Проверить ключ**.
   Кнопка отправляет одну короткую фразу и показывает результат — так сразу
   видно, что ключ принят и биллинг включён.

DeepL и Azure подключаются так же, только переменными `DEEPL_API_KEY` либо
`AZURE_TRANSLATOR_KEY` + `AZURE_TRANSLATOR_REGION`.

## Когда происходит перевод

- **Новый пост** — сразу после публикации (из админки или после импорта из
  Telegram-канала), в фоне: ответ админке не ждёт API. К моменту, когда на
  английскую версию придёт первый гость или робот, перевод уже лежит в БД.
- **Старые посты и страницы проектов** — лениво: перевода нет, пока никто не
  открыл английскую версию страницы. Первый заход запускает перевод и ждёт его
  не дольше 2,5 секунд; если API не успел, страница отдаётся на русском, а
  перевод дописывается в кеш и достанется следующему посетителю.
- **Списки** (главная, «Публикации», «Проекты») переводят только заголовки,
  превью и короткие описания — тела постов туда не попадают.
- **RSS** берёт только готовые переводы и никогда не обращается к API.

Оба режима отключаются галочками в админке (вкладка **Переводы**).

## На чём экономится лимит

- **Кеш в SQLite.** Ключ — сущность + поле + язык + SHA1 исходного текста.
  Изменили пост → хеш изменился → перевод помечен устаревшим и делается заново.
  Не изменили — API не вызывается вообще.
- **Эвристика «текст уже английский».** Если в тексте меньше 15 % кириллицы
  (типичный README), он сохраняется как есть за 0 символов.
- **Дедупликация.** Если одну и ту же страницу одновременно открыли несколько
  человек, запрос к API уходит один — остальные ждут его результат.
- **Батчинг.** Заголовки и превью всего списка уходят одним запросом, длинный
  HTML режется по границам блоков, чтобы теги оставались парными.
- **Потолок символов.** Поле длиннее 40 000 символов не переводится совсем
  (один такой README мог бы съесть месячный лимит), а общий месячный счётчик
  останавливает переводы до начала следующего месяца.

## Админка: вкладка «Переводы»

- Активный провайдер, есть ли ключ, ссылка на его консоль с квотами.
- Расход за текущий месяц: прогресс-бар, символы, число запросов и ошибок.
  Для DeepL рядом показывается реальный расход из API провайдера.
- Таблица всех провайдеров с бесплатными лимитами — видно, куда переезжать,
  если упёрлись в потолок.
- Последняя ошибка API с человеческим объяснением и кнопкой сброса паузы.
- Список публикаций со статусом (`переведён` / `устарел` / `нет перевода`),
  оценкой стоимости в символах и кнопкой перевода по одной.
- Кнопки: проверить ключ, перевести всё непереведённое (с оценкой расхода
  до нажатия), перевести блок «обо мне».

## Как обрабатываются ошибки API

| Ситуация | Что делает сайт |
| --- | --- |
| Лимит исчерпан (Google 429/`quotaExceeded`, DeepL 456, Azure 403) | Помечает паузу до 1-го числа следующего месяца, страницы отдаются на русском, в админке — красный блок с объяснением |
| Неверный ключ / API не включён (401, 403, `API key not valid`) | Пауза 30 минут, чтобы не долбить API на каждый запрос страницы |
| Слишком много запросов (429) | Пауза 5 минут |
| Сеть, таймаут (15 с), непонятный ответ | Пауза 3 минуты |
| Текст слишком большой | Поле пропускается, остальные переводятся |

Ни одна из ошибок не роняет страницу: посетитель всегда получает контент,
в худшем случае — на русском языке. Все ошибки видны в админке и в логах
контейнера (`[translate] …`).
