# SEO: индексация, смена домена, две языковые версии

## Что сайт отдаёт поисковикам

| Что | Где | Зачем |
| --- | --- | --- |
| `<link rel="canonical">` | каждая страница | одна страница — один канонический адрес, без дублей от `?utm=…` |
| `<link rel="alternate" hreflang="ru\|en\|x-default">` | каждая страница | связывает `/publications/12` и `/en/publications/12` как одну страницу на двух языках |
| `sitemap.xml` | `/sitemap.xml` | все страницы обоих языков с `lastmod` и `xhtml:link`-альтернативами |
| `robots.txt` | `/robots.txt` (динамический) | на публичном хосте — ссылка на sitemap, на админ-поддомене — полный `Disallow: /` |
| Open Graph и Twitter Card | каждая страница | нормальные превью в Telegram, X и поиске |
| JSON-LD | главная (`Person`, `WebSite`), проекты (`SoftwareSourceCode`), публикации (`BlogPosting`), везде — `BreadcrumbList` | расширенные сниппеты и связь сайта с автором |
| `Vary: Accept-Language, Cookie` | HTML-ответы | кеши не подменяют язык страницы |
| RSS | `/rss.xml` и `/en/rss.xml` | ленты на обоих языках |
| IndexNow | `/<ключ>.txt` + пинг при публикации | Bing и Яндекс узнают о новом посте за секунды |

Автоопределение языка не мешает индексации: если запрос пришёл от робота
(Googlebot, YandexBot, Bingbot и т. д.), редиректа по `Accept-Language` не
происходит — бот получает ровно ту версию, которую запросил.

## После смены домена: что сделать руками

Код уже отдаёт 301 со старых доменов (`ALIAS_DOMAINS` в `.env`,
см. [DEPLOY 2.1](DEPLOY.md#21-дополнительные-домены-алиасы)) — это главное
условие переноса. Остальное делается в панелях поисковиков и в коде не живёт:

1. **Google Search Console.** Добавить оба ресурса — старый и новый домен
   (проще всего Domain property через DNS-запись TXT). Подтвердить права можно
   и мета-тегом: положите значение в `GOOGLE_SITE_VERIFICATION`, и тег
   появится на всех страницах.
2. **«Изменение адреса»** (Settings → Change of address) в ресурсе старого
   домена. Это работает, только если старый домен ещё жив и отдаёт 301 на
   новый — то есть его нельзя отпускать сразу.
3. **Отправить sitemap** нового домена: Sitemaps → `https://normno.com/sitemap.xml`.
4. **Проверить главные страницы** через URL Inspection → Request indexing:
   главная, `/projects`, `/publications` и пара свежих постов.
5. **Яндекс.Вебмастер.** Добавить сайт (мета-тег — `YANDEX_VERIFICATION`),
   в разделе «Переезд сайта» указать новый главный домен, отправить sitemap.
6. **IndexNow.** Сгенерировать ключ (любые 8–128 hex-символов, например
   `openssl rand -hex 16`), положить в `INDEXNOW_KEY`, перезапустить контейнер
   и открыть `https://normno.com/<ключ>.txt` — там должен лежать сам ключ.
   Дальше каждый новый пост уходит в Bing и Яндекс автоматически.
7. **Обновить внешние ссылки** на новый домен: профиль GitHub, шапка
   Telegram-канала, описание YouTube, ссылки в README репозиториев. Обратные
   ссылки — самый весомый сигнал при переезде.

Ожидание: Google переиндексирует небольшой сайт за 1–4 недели после
«Изменения адреса», Яндекс — за 2–6 недель. Пока идёт переезд, старый домен
должен оставаться зарегистрированным и отвечать 301.

## Как проверить, что всё на месте

```bash
curl -s https://normno.com/robots.txt
curl -s https://normno.com/sitemap.xml | head -20
curl -sI https://normno.com/ | grep -i vary
curl -s https://normno.com/ | grep -E 'canonical|hreflang'
# бот не должен получать редирект по языку
curl -s -o /dev/null -w '%{http_code}\n' -A 'Googlebot' -H 'Accept-Language: en-US' https://normno.com/
# на админ-хосте индексация закрыта полностью
curl -s https://admin.normno.com/robots.txt
```

Полезные внешние проверки: Google Rich Results Test (JSON-LD),
Search Console → «Международный таргетинг» (ошибки hreflang),
PageSpeed Insights (Core Web Vitals — тоже фактор ранжирования).

## Что ещё влияет на выдачу и уже сделано

- Заголовки и описания страниц различаются и содержат ключевые слова
  («Kotlin Multiplatform», названия проектов), а не один общий текст.
- У английской версии свои `title`/`description`, а не машинный перевод
  русских — их видно в `src/lib/i18n/dict.ts`.
- Машинно переведённые страницы честно помечены сноской внизу: поисковики
  не любят выдавать машинный перевод за авторский текст.
- 404 отдаётся с кодом 404 и `noindex`, админка — `noindex, nofollow`
  плюс отдельный поддомен с `Disallow: /`.
- Страницы кешируются (`Cache-Control: public, max-age=60`) и не ходят во
  внешние API в момент запроса — быстрый ответ сервера тоже учитывается.
