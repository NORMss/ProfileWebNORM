# Telegram-бот: как он устроен, развертывание и использование

## Как это работает

Отдельного процесса-бота в проекте **нет** — и он не нужен. «Бот» здесь — это
бот-аккаунт Telegram (созданный через @BotFather), от имени которого само
приложение сайта ходит в [Telegram Bot API](https://core.telegram.org/bots/api)
по HTTPS в двух направлениях:

```
                    ┌─────────────────────────────┐
   импорт и правки        getUpdates              │
  ┌──────────────── Bot API ◄─────────────────────┤
  ▼                                               │
SQLite (posts) ── сайт /publications        Telegram-канал
  ▲                                               ▲
  └──────────────── Bot API ──────────────────────┘
   публикация и правки   sendRichMessage /
                         editMessageText
```

### Сайт → канал (публикация в markdown)

Используются **rich-сообщения Bot API 10.1** (июнь 2026): метод
`sendRichMessage` принимает markdown как есть — Telegram сам рендерит
заголовки, списки, цитаты, код и картинки (`![](url)`), без ручной
конвертации. Если Bot API сервер старее 10.1, приложение автоматически
падает на классический `sendMessage` с parse_mode=HTML (заголовки — жирным,
списки — «• …», картинки — ссылками; лимит 4096 символов, длинное
обрезается со ссылкой «Читать полностью →»).

### Канал → сайт (импорт)

Приложение периодически (вместе с GitHub-синком, по умолчанию раз в
30 минут) и по кнопке «Парсить посты» вызывает `getUpdates` и забирает:

- **новые посты** (`channel_post`) — первая строка становится заголовком,
  остальное телом;
- **правки постов** (`edited_channel_post`) — пост, импортированный из
  Telegram, обновляется и на сайте.

Offset хранится в БД — каждый апдейт обрабатывается один раз.

### Правила синхронизации правок (без конфликтов и петель)

| Пост создан | Правится на сайте | Правится в Telegram |
| --- | --- | --- |
| на сайте (`ADMIN`) | сообщение в канале обновляется (`editMessageText`) | игнорируется — для таких постов источник истины сайт |
| в Telegram (`TELEGRAM`) | обновление в канал **отправляется** (если бот имеет право «Edit messages») | пост на сайте обновляется |

### Дубликаты

У поста, отправленного из сайта, сохраняется `message_id`. Когда этот же
пост прилетает обратно через `getUpdates`, он распознаётся и не
импортируется второй раз.

### Фото в постах

Картинки добавляются в markdown (`![](url)`): кнопкой «🖼 Прикрепить фото»
(файл сохраняется на сервере в `data/uploads/posts`, отдаётся с сайта по
`/media/post/…`) или обычной ссылкой на внешнее изображение. При отправке
в Telegram относительные ссылки автоматически превращаются в абсолютные
(`SITE_URL/media/…`) — чтобы Telegram мог скачать картинку, сайт должен
быть доступен из интернета. В HTML-фолбэке картинки отправляются ссылками.

## Развертывание (один раз)

1. **Создайте бота**: напишите [@BotFather](https://t.me/BotFather) → `/newbot`
   → задайте имя и username. Токен вида `1234567890:AA…` → в `.env` как
   `TELEGRAM_BOT_TOKEN`.
2. **Добавьте бота администратором канала**: настройки канала →
   «Администраторы». Для импорта достаточно самого факта админства; для
   публикации с сайта включите право **«Публикация сообщений» (Post
   messages)**, для обновления правок — **«Редактирование сообщений»
   (Edit messages)**.
3. **Заполните `.env`**:

   ```env
   TELEGRAM_BOT_TOKEN=1234567890:AA...
   # username канала (для публичного) или числовой id -100… (для приватного)
   TELEGRAM_CHANNEL=@normno
   ```

4. **Перезапустите приложение**: `docker compose up -d --build`.

## Использование

| Действие | Где |
| --- | --- |
| Импортировать посты/правки канала на сайт | Админка → «Публикации» → «↧ Парсить посты» (и автоматически по крону) |
| Проверить подключение бота | Админка → «Публикации» → «🔍 Диагностика» |
| Опубликовать пост сразу на сайт и в канал | Галочка «Сразу отправить в Telegram-канал» → «Опубликовать» |
| Дослать в канал существующий пост | Кнопка «📨» напротив поста |
| Обновить сообщение в канале | Просто отредактируйте пост на сайте — правка уедет сама |
| Прикрепить фото | Кнопка «🖼 Прикрепить фото» или `![](https://…)` в markdown |

## Бэкапы в Telegram

Тот же бот умеет присылать бэкап всех данных сайта (SQLite + загруженные
картинки) **в личный чат** — архив `normno-backup-<дата>.tar.gz`:

1. Узнайте свой личный chat_id: напишите боту
   [@userinfobot](https://t.me/userinfobot) — он ответит вашим `Id`.
2. Напишите вашему боту `/start` (иначе Telegram не даст боту писать вам первым).
3. В `.env` добавьте `TELEGRAM_BACKUP_CHAT_ID=<ваш id>` и перезапустите приложение.

После этого бэкап уходит **ежедневно в 04:30** (по времени сервера), а в
админке на вкладке «Публикации» появляется кнопка **«💾 Бэкап в Telegram»**
для ручного снапшота. Копия БД делается через SQLite online-backup — она
консистентна даже при одновременной записи. Восстановление: распаковать
архив в каталог `data/` (`site.db` + `uploads/`) и перезапустить приложение.

⚠️ Указывайте именно личный chat_id — не id публичного канала, иначе бэкап
с вашими данными окажется в открытом доступе. Лимит документа у ботов —
50 МБ; при превышении бэкап не отправится и напишет ошибку в лог.

## Импорт «не видит» посты — чек-лист

Нажмите **«🔍 Диагностика»** в админке и проверьте по порядку:

1. **Установлен webhook** — самая частая причина: `getUpdates` и webhook
   взаимоисключающи, диагностика покажет предупреждение. Снять:
   `curl "https://api.telegram.org/bot<TOKEN>/deleteWebhook"`.
2. **Приватный канал + `TELEGRAM_CHANNEL=@имя`** — у приватных каналов нет
   username, фильтр не совпадает и посты пропускаются. Укажите числовой id
   (`-100…`): перешлите пост канала боту
   [@userinfobot](https://t.me/userinfobot) или посмотрите `chat.id` в
   ответе `getUpdates`. В логах приложения пропуски видны строками
   `[tg] пропущен пост из чата …`.
3. **Посты старше 24 часов или созданные до добавления бота** — Telegram
   хранит апдейты только 24 часа, и бот получает лишь то, что появилось
   после его добавления в канал. Старые посты придётся создать на сайте
   заново.
4. **Апдейты уже забрал кто-то другой** — если этим же токеном пользуется
   другой скрипт/сервис, он «съедает» getUpdates. Один токен — один
   потребитель.
5. Бот вообще не админ канала — добавьте в администраторы (обычного
   участника каналов у ботов не бывает).

## Прочие ограничения

- Telegram-разметка постов канала при **импорте** — это plain-текст
  сообщения; вложенные фото/альбомы каналов пока не переносятся на сайт.
- Правка поста в канале старше 48 часов может быть недоступна боту
  (ограничение Telegram) — сайт покажет предупреждение.
- В HTML-фолбэке (Bot API < 10.1) лимит `sendMessage` — 4096 символов.
