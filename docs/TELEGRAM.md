# Telegram-бот: как он устроен, развертывание и использование

## Как это работает

Отдельного процесса-бота в проекте **нет** — и он не нужен. «Бот» здесь — это
бот-аккаунт Telegram (созданный через @BotFather), от имени которого само
приложение сайта ходит в [Telegram Bot API](https://core.telegram.org/bots/api)
по HTTPS в двух направлениях:

```
                    ┌─────────────────────────────┐
   импорт (cron/кнопка)   getUpdates              │
  ┌──────────────── Bot API ◄─────────────────────┤
  ▼                                               │
SQLite (posts) ── сайт /publications        Telegram-канал
  ▲                                               ▲
  └──────────────── Bot API ──────────────────────┘
   публикация (кнопка/чекбокс)  sendMessage
```

- **Импорт канала → сайт**: приложение периодически (вместе с GitHub-синком,
  по умолчанию раз в 30 минут) и по кнопке «Парсить посты» вызывает
  `getUpdates` и забирает новые посты канала (`channel_post`). Первая строка
  поста становится заголовком, остальное — телом. Offset хранится в БД, каждый
  пост импортируется один раз.
- **Сайт → канал**: при создании публикации в админке можно поставить галочку
  «Сразу отправить в Telegram-канал», а для уже существующих постов — нажать
  кнопку «📨» в списке. Приложение вызывает `sendMessage` с `parse_mode=HTML`:
  markdown поста конвертируется в разметку, которую понимает Telegram
  (жирный/курсив/код/цитаты/ссылки; заголовки становятся жирными строками,
  списки — «• …»). Если пост длиннее лимита Telegram (4096 символов), текст
  обрезается и добавляется ссылка «Читать полностью →» на сайт.
- **Защита от дублей**: у отправленного поста сохраняется `message_id`.
  Собственный пост бота, прилетевший обратно через `getUpdates`, по этому id
  распознаётся и не импортируется второй раз.

## Развертывание (один раз)

1. **Создайте бота**: напишите [@BotFather](https://t.me/BotFather) → `/newbot`
   → задайте имя и username. Получите токен вида `1234567890:AA…` —
   он идёт в `.env` как `TELEGRAM_BOT_TOKEN`.
2. **Добавьте бота администратором канала**: в настройках канала →
   «Администраторы» → добавьте бота. Для импорта достаточно самого факта
   админства; для публикации с сайта включите право **«Публикация сообщений»
   (Post messages)**.
3. **Заполните `.env`**:

   ```env
   TELEGRAM_BOT_TOKEN=1234567890:AA...
   # username канала (для публичного) или -100… (числовой id для приватного)
   TELEGRAM_CHANNEL=@normno
   ```

   Числовой id приватного канала можно узнать, переслав любой пост канала боту
   [@userinfobot](https://t.me/userinfobot) или посмотрев `chat.id` в ответе
   `getUpdates`.

4. **Перезапустите приложение**: `docker compose up -d --build`.

## Использование

| Действие | Где |
| --- | --- |
| Импортировать посты канала на сайт | Админка → «Публикации» → «↧ Парсить посты» (и автоматически по крону) |
| Опубликовать новый пост сразу и на сайт, и в канал | Админка → «Публикации» → написать пост → галочка «Сразу отправить в Telegram-канал» → «Опубликовать» |
| Дослать в канал уже существующий пост сайта | Кнопка «📨» напротив поста в списке «Все публикации» |
| Понять, есть ли пост в канале | Метка «✓TG» напротив поста |

## Ограничения и подводные камни

- `getUpdates` отдаёт только посты, появившиеся **после** добавления бота
  в канал (и не старше 24 часов с момента появления). Старые посты придётся
  перенести руками или опубликовать заново.
- У бота не должен быть настроен **webhook** — `getUpdates` и webhook
  взаимоисключающи. Если когда-то настраивали webhook, снимите его:
  `curl https://api.telegram.org/bot<TOKEN>/deleteWebhook`.
- Telegram-разметка беднее markdown: картинки, таблицы и заголовки в постах
  канала не отображаются (заголовки становятся жирным текстом, картинки
  выбрасываются). Полная версия поста всегда доступна на сайте.
- Редактирование поста на сайте **не** обновляет уже отправленное сообщение
  в канале (и наоборот) — синхронизируется только факт публикации.
- Лимит `sendMessage` — 4096 символов; длинные посты обрезаются со ссылкой
  на полную версию.
