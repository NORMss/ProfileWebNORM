# Скорость публичных страниц

Что сделано, почему именно так и что осталось. Всё ниже касается **публичной**
части: админка — одностраничное приложение на Svelte, её вес посетителей сайта
не касается и намеренно не трогался.

## Замер

Lighthouse, мобильный профиль (Moto G Power, throttling 1638 кбит/с, RTT
150 мс) — тот же, на котором работает PageSpeed Insights. Локальный стенд
собран по боевому отчёту от 25 августа: 23 проекта, 27 публикаций, аватар
2352×2351 весом 2,4 МБ и обложки-скриншоты из README на чужом хосте.
На этом стенде старая версия повторяет боевые цифры (perf 75, a11y 84),
поэтому сравнение честное — данные у обеих версий одинаковые.

| Метрика (главная) | main | стало |
| --- | --- | --- |
| Performance | 75 | **100** |
| Accessibility | 84 | **100** |
| Best Practices | 100 | 100 |
| SEO | 100 | 100 |
| LCP | 17,4 c | **1,4 c** |
| FCP | 1,4 c | 1,2 c |
| Speed Index | 1,4 c | 1,2 c |
| TBT / CLS | 0 мс / 0 | 0 мс / 0 |

`/projects` и `/publications` — тоже 100 по всем четырём категориям.

Что приезжает в браузер на первую загрузку главной:

| | main | стало |
| --- | --- | --- |
| Вес страницы целиком | 3 578 КБ (боевой отчёт) | **77 КБ** |
| В том числе картинок | ~3 500 КБ | **4 КБ** |
| Запросов к своему серверу | 10 | 4 |

| Узлов DOM, `/projects` | 278 | 158 |
| Узлов DOM, `/publications` | 248 | 125 |

Локальный замер не заменяет PageSpeed Insights: там настоящая сеть и реальная
база. Но раз старая версия на стенде даёт ровно боевые 75 и 84, разнице между
«до» и «после» верить можно.

## Что изменилось

### Сервер отдаёт меньше данных

`SELECT *` на списках поднимал из SQLite колонки, которые списку не нужны:
`readme_html` каждого проекта (сотни килобайт на строку) и `body_md` /
`body_html` каждого поста. Появились списочные проекции — `getVisibleRepoCards`
и `getPublishedPostCards` (`src/lib/queries.ts`), они читают только поля
карточки.

Превью поста раньше считалось на каждый показ списка: `markdown-it` +
`sanitize-html` по каждому посту в каждом запросе. Теперь превью и хеш тела
лежат в колонках `posts.excerpt` и `posts.body_hash` и считаются один раз при
сохранении — общей функцией `postContentFields` (`src/lib/posts.ts`), которую
зовут и админка, и импорт из Telegram. Постам, сохранённым раньше, поля
досчитываются один раз при старте (`backfillPostExcerpts`).

### Ноль внешних JS и CSS

Виджет Spotify был островком Svelte с `client:load` — ради опроса раз в
20 секунд на каждую загрузку главной приезжал рантайм Svelte. Он переписан
в обычный компонент Astro с маленьким скриптом (`SpotifyWidget.astro`), и
Svelte остался только в админке. Опрос ставится на паузу, когда вкладка
неактивна.

Стили инлайнятся в HTML (`build.inlineStylesheets: 'always'`): CDN перед
сайтом нет, поэтому отдельный файл стилей стоил лишнего похода на сервер
перед первой отрисовкой. Сжатые ~20 КБ дешевле, чем ещё один round-trip.

### Списки грузятся пачками

Обе страницы отдают первую пачку карточек готовым HTML — она попадает
в разметку и в индекс, — а дальше карточки дорисовываются при прокрутке:

- **Публикации**: `IntersectionObserver` на «подвале» списка тянет
  `/api/publications?offset=…`, который отдаёт готовый HTML следующей пачки.
- **Проекты**: весь список едет в странице компактным JSON (однобуквенные
  ключи, `src/lib/cards.ts`), по нему же работают вкладки, поиск и сортировка —
  без запросов к серверу и без задержки на ввод.

Разметку карточки рисует общий шаблон (`postCardHtml`, `projectCardHtml`), так
что дорисованная карточка ничем не отличается от отданной сервером. Классы у
них глобальные — scoped-атрибуты Astro на разметку из скрипта не попадают.

Без JavaScript обе страницы дают ссылку `?all=1`, которая отдаёт список
целиком; поисковикам все позиции видны в JSON-LD (`ItemList` на проектах,
`Blog` на публикациях) и в `sitemap.xml`.

### Отрисовка

Главный расход на телефоне был не в байтах, а в кадрах: три размытых пятна
фона анимировались бесконечно, а над ними лежал десяток панелей с
`backdrop-filter` — каждый кадр браузер пересчитывал размытие подложки
на весь экран. Анимация фона осталась только там, где она бесплатна
(широкий экран, мышь, `prefers-reduced-motion: no-preference`), радиус
размытия «стекла» вынесен в `--glass-blur` и уменьшен на узких экранах,
а с плашки на карточке проекта `backdrop-filter` убран совсем — под ней
непрозрачный скриншот, размывать нечего.

Блоки ниже первого экрана (тепловая карта на ~370 ячеек, карточки списков,
блок последних публикаций) размечаются через `content-visibility: auto`
с `contain-intrinsic-size`: до прокрутки браузер не тратит на них ни кадра,
а длина полосы прокрутки остаётся правильной.

### Картинки

Это была главная проблема: на боевом сайте страница весила 3,5 МБ, и почти всё
это — картинки, отданные в исходном размере.

**Аватар** отдавался файлом из админки как есть: 2352×2351, 2 132 КБ, а
показывается он кружком 194×179. На мобильном канале PageSpeed эти 2 МБ
качаются больше десяти секунд — отсюда и LCP 15 с. Теперь `/media/avatar`
отдаёт уменьшенную WebP-копию (440 px хватает и экранам двойной плотности),
объявленную в `<head>` через `preload` + `fetchpriority="high"`.

**Обложки проектов** — второй по величине источник байтов: в блоке «Последние
обновления» стояли прямые ссылки на скриншоты из README (872 КБ и 476 КБ,
1110×1116 и 1425×1424) — в миниатюре 52×52. Теперь и загруженные, и внешние
обложки идут через `/media/repo/<id>`: он приводит картинку к нужной ширине
(`?size=thumb` — 160 px для миниатюры, по умолчанию 1000 px для карточки),
кладёт WebP-копию на диск и дальше отдаёт её оттуда. К чужому хосту сайт
сходит один раз за картинку, а не на каждый показ страницы; имя кеша содержит
хеш адреса, поэтому смена обложки в админке подхватывается сама. Если sharp
недоступен или чужой хост не ответил, запрос отвечает редиректом на исходный
адрес — карточка не остаётся пустой.

Копии пишутся через временный файл с атомарным `rename`, а параллельные
запросы за одной картинкой ждут общий результат: отдать недописанный файл
с длинным кешем нельзя.

Обложке без своей картинки по-прежнему соответствует og-image GitHub — он и
так лёгкий и лежит на CDN, заворачивать его к себе смысла нет; соединение
с этим хостом открывается заранее через `preconnect`. У всех картинок заданы
размеры или соотношение сторон — CLS = 0.

### Доступность

- `user-scalable=no` убран из `viewport`: двойной тап-зум и так снят через
  `touch-action: manipulation`, а запрет масштабирования отбирал у людей
  возможность увеличить мелкий текст.
- Приглушённые цвета текста на светлой теме пересчитаны так, чтобы даже
  12-пиксельная подпись брала контраст 4.5:1 (было 3.5:1 на датах публикаций).
- Доступное имя кнопки языка начинается с видимой надписи (`RU`/`EN`).
- Переключатель GitHub / Claude в тепловой карте был размечен как `role="tablist"`
  с обычными кнопками внутри. Такая разметка требует детей с `role="tab"` и
  связанных с ними панелей, а панель здесь одна — кнопки только перекрашивают
  ту же карту. Теперь это группа кнопок-переключателей с `aria-pressed`. Этот же
  дефект валил новую категорию PageSpeed «Agentic Browsing»: ИИ-агент читает
  дерево доступности, и сломанный `tablist` мешает ему не меньше, чем
  скринридеру.

### Выбор языка без редиректа

Браузер с `Accept-Language: en` на `https://example.com/` получал 302 на `/en`
и только потом страницу — лишний поход на сервер перед первой отрисовкой,
~0,6 с на мобильном профиле Lighthouse («Avoid multiple page redirects»).
Тот же редирект получал и сам PageSpeed Insights: его Chrome ходит с
английской локалью.

Теперь по языку браузера никто никуда не перебрасывается — как и рекомендует
Google для многоязычных сайтов. Вместо редиректа страница показывает вверху
полосу «This page is also available in English» со ссылкой; полоса приходит
уже отрисованной с сервера, поэтому ничего не сдвигает (CLS остаётся 0), а
закрыть её можно крестиком — выбор запоминается в куке `lang_hint`.

Редирект остался там, где язык выбрал сам посетитель: `?hl=` от переключателя
ставит куку `lang`, и по ней «чистый» адрес возвращает в выбранную версию.
Ни у первого захода, ни у робота этой куки нет — значит, нет и редиректа.

Побочный эффект: определение робота по `User-Agent` больше не нужно (оно было
нужно, чтобы не редиректить ботов), функция `isCrawler` удалена. Полоса
показывается только при наличии `Accept-Language`, а роботы его обычно не
шлют — в индекс попадает страница без неё.

Замер после правки (мобильный профиль, локаль en-US — как у PageSpeed Insights):

| Страница | FCP | LCP | CLS | Редиректы |
| --- | --- | --- | --- | --- |
| `/` | 0,9 c | 1,1 c | 0 | нет |
| `/projects` | 1,0 c | 1,0 c | 0 | нет |
| `/publications` | 0,8 c | 0,9 c | 0 | нет |

## Что осталось

**Контраст в тёмной теме** не проверялся автоматически (Lighthouse ходит со
светлой), значения там не менялись.
